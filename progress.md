Finding: in Demonio the LL cluster (cpu4-7) was found stuck at 1208 MHz after ~7 h of use (56 suspends). Driver code: requests are rejected (-EPERM) while dvfs_disable_by_suspend; "performance" only re-targets on a limits event, so a lost request is never retried. A real governor change or a scaling_min_freq rewrite re-targets. Not reproducible over USB (no suspend while plugged + stay_on).
Ruling: Demonio starts a watchdog (`profile.sh kick`, setsid, 9>&- so it never holds the lock, killed with -9 on every profile change): every 10 s, a cluster below scaling_max_freq -> rewrite scaling_min_freq + `log -t g25_kick`. Verified: starts, never holds the lock, dies on switch. NOT verified against the natural stuck case — cost if wrong: Demonio may still drop LL to 1208 after resume.
Artifact (mine, cleared): `echo 5 > /proc/cpufreq/MT_CPU_DVFS_LL/cpufreq_oppidx` sets dvfs_disable_by_procfs=true and pins OPP 5 until `echo -1` — never write it again.
